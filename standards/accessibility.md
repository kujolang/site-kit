# Accessibility standard

SiteKit targets WCAG 2.2 AA for source components, documented usage, and tested reference compositions. Prefer native HTML before ARIA. Interactive components require keyboard operation, visible focus, hover, active, disabled, and loading states where applicable. Motion must respect `prefers-reduced-motion`. Color cannot be the only status indicator. Dialogs require focus entry, containment, Escape dismissal where allowed, restoration, and a semantic title. Forms require visible labels, descriptions, errors, and useful autocomplete values. Tables require captions and scoped headers. Downstream consumers remain responsible for their complete page content and accessibility testing; SiteKit does not certify arbitrary compositions.
